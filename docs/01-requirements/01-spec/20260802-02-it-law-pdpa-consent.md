# 20260802-02 - การปฏิบัติตามกฎหมาย IT และ PDPA (เก็บ Log 90 วัน + Consent การใช้งาน Google Analytics/IP Address)

- **ประเภท:** Non-functional requirement / Compliance
- **สถานะเอกสาร:** Draft
- **วันที่สร้าง:** 2026-08-02

## ขอบเขต (Scope)

**อยู่ในขอบเขต (In scope)**

- เก็บข้อมูลจราจรทางคอมพิวเตอร์ (system/access log) ของระบบ เป็นระยะเวลาไม่น้อยกว่า **90 วัน** ตามข้อกำหนดกฎหมาย IT ของไทย
- แสดง **Consent Banner** แจ้งผู้ใช้งานที่เป็นผู้ซื้อ (ลูกค้า) ก่อนเริ่มเก็บ/ใช้ข้อมูล เกี่ยวกับ:
  - การใช้งาน Google Analytics (หรือเครื่องมือ analytics อื่นที่คล้ายกัน)
  - การเก็บ IP Address และข้อมูลที่เกี่ยวข้อง (เช่น user-agent, timestamp การเข้าใช้งาน)
- บันทึกสถานะการให้ความยินยอม (consent) ของผู้ใช้งานแบบพื้นฐาน (ยอมรับ/ปฏิเสธ) — ระดับ MVP

**นอกขอบเขต (Out of scope) — เฟสนี้**

- ระบบจัดการสิทธิ์เจ้าของข้อมูลแบบเต็มรูปแบบ (คำร้องขอเข้าถึง/แก้ไข/ลบข้อมูลส่วนบุคคลผ่านระบบอัตโนมัติ)
- การจัดทำ Records of Processing Activities (ROPA) แบบเต็มรูปแบบ และ workflow ของเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO)
- Consent แยกประเภทสำหรับการตลาด/marketing opt-in (อาจพิจารณาเพิ่มในเฟสถัดไป)

## รายละเอียด (Description)

ระบบ (รวมถึงระบบสั่ง order จากโต๊ะใน [20260802-01-self-order-from-table.md](20260802-01-self-order-from-table.md)) ต้องปฏิบัติตามข้อกำหนดกฎหมายไทย 2 ฉบับหลัก:

1. **พ.ร.บ. ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์** — กำหนดให้ผู้ให้บริการเก็บรักษาข้อมูลจราจรทางคอมพิวเตอร์ (log) ไว้ไม่น้อยกว่า 90 วัน เพื่อให้พนักงานเจ้าหน้าที่สามารถตรวจสอบย้อนหลังได้หากจำเป็น
2. **พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA)** — กำหนดให้ต้องแจ้งวัตถุประสงค์และขอความยินยอมจากเจ้าของข้อมูลก่อนเก็บ/ใช้/เปิดเผยข้อมูลส่วนบุคคล ซึ่งรวมถึง IP Address และข้อมูลที่เก็บผ่านเครื่องมืออย่าง Google Analytics

## Acceptance Criteria

- [ ] ระบบเก็บ log การเข้าใช้งาน/ทำรายการที่จำเป็น (เช่น IP, timestamp, url ที่เข้าถึง) ไว้อย่างน้อย 90 วัน และมีกลไกลบ/หมุนเวียน log ที่เกินอายุ 90 วัน
- [ ] ผู้ใช้งานเห็น consent banner ก่อนมีการเก็บข้อมูลผ่าน Google Analytics หรือ IP Address ตั้งแต่ครั้งแรกที่เข้าใช้งาน
- [ ] ผู้ใช้งานสามารถเลือก "ยอมรับ" หรือ "ปฏิเสธ" การใช้งาน analytics ได้ และระบบบันทึกการเลือกนั้นไว้
- [ ] มีหน้า Privacy/Cookie Policy อธิบายรายละเอียดการเก็บและใช้ข้อมูล ที่ consent banner ลิงก์ไปถึง

## ข้อเสนอแนะเพิ่มเติม (Recommendations)

- ควรทำ **Privacy Policy / Cookie Policy** เป็นหน้าเอกสารแยกต่างหากที่ consent banner ลิงก์ไปถึง เพื่อให้ครบตามข้อกำหนดการแจ้งวัตถุประสงค์ของ PDPA
- แนะนำให้ตั้งค่า **auto-purge log ที่เกิน 90 วัน** โดยอัตโนมัติ เพื่อลดความเสี่ยงจากการเก็บข้อมูลเกินความจำเป็น (data minimization)
- แนะนำพิจารณาแยกประเภท cookie/analytics เป็น essential vs non-essential และ**ไม่โหลด Google Analytics ก่อนได้รับความยินยอม** เพื่อให้สอดคล้องกับแนวปฏิบัติ PDPA ที่เข้มงวด
- เมื่อเข้าสู่ขั้นตอนออกแบบเชิงเทคนิค (`docs/02-design/02-technical/`) ควรมีเอกสาร Data Retention Policy ระบุตำแหน่งจัดเก็บ log, วิธี purge, และผู้มีสิทธิ์เข้าถึง log แยกต่างหาก

## จุดที่ยังไม่ได้ระบุ / ควรยืนยันเพิ่มเติม (Open Points)

- ยังไม่ระบุว่าระบบจะเก็บข้อมูลส่วนบุคคลอื่นเพิ่มเติมหรือไม่ (เช่น เบอร์โทรศัพท์สำหรับใบเสร็จ, อีเมล, ข้อมูลสมาชิก) ซึ่งจะขยายขอบเขตข้อกำหนด PDPA ที่ต้องดูแลเพิ่มเติมในอนาคต หากมีการเพิ่มระบบสมาชิก/loyalty ในภายหลัง

## ความสัมพันธ์กับเอกสารอื่น (Requirement Cross-reference Analysis)

เอกสารนี้อ้างอิงถึง requirement [20260802-01-self-order-from-table.md](20260802-01-self-order-from-table.md) เนื่องจากระบบสั่ง order จากโต๊ะเป็นหนึ่งใน touchpoint ที่จะมีการเก็บ IP Address และใช้งาน Google Analytics

**วิเคราะห์ว่าควรสร้างเอกสารใหม่หรือไม่:** ตัดสินใจสร้างเป็น **เอกสารใหม่แยกต่างหาก** แทนที่จะรวมไว้ใน 20260802-01 เนื่องจากข้อกำหนดด้านกฎหมาย IT และ PDPA เป็นข้อกำหนดเชิง compliance ที่ครอบคลุมทั้งระบบ (cross-cutting) ไม่ได้ผูกกับฟีเจอร์สั่ง order จากโต๊ะเพียงอย่างเดียว และจะยังคงมีผลบังคับใช้ต่อไปแม้จะมีการเพิ่มฟีเจอร์อื่นในอนาคต การแยกเอกสารทำให้ติดตามและอัปเดตข้อกำหนดกฎหมายได้อิสระจากการเปลี่ยนแปลงของแต่ละฟีเจอร์
